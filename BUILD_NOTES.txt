UNLIMITED UV
UnlimitedUv resolves InGameHelpers.GetLocalNolanBehaviour on every operation.
It requires an active local player with an attached entity that is owned or
controlled locally, in the existing solo/host scope. It matches the player's
batteryAttribute by native pointer, not a managed wrapper or name-only search.
Remote batteries and all other attributes retain native behavior. No keyboard
or VR binding was added. Charge is automatic and independent of freeze/flight.

NolanBehaviour.Attached postfix fills after native difficulty initialization.
OnUpdate retries if the local player or battery was not yet available, refills
a new player, and follows capacity changes. The native Value setter updates
UI/events. Easy/Normal/Hard retain their current maximum, including any active
battery bonus. Nightmare enables only the battery's NightmareModeBattery state
and uses its native 60-unit capacity with isUsingBatteryBonus, following the
native battery item's charge sequence. It never changes character difficulty.
A missing/invalid capacity produces a UV error instead of guessing.

Three Attribute hooks are restricted to that exact local battery:
- set_Value prefix replaces incoming charge with full capacity, including the
  Nightmare zero write on spawn or returning from purgatory. Native setter
  notifications and scheduling still execute.
- UpdateValue prefix cancels and clears the scheduled event, fills if needed,
  and suppresses the native direct drain before the empty-destination callback.
  This avoids a transient empty charge that could stop the UV ability.
- ResetValue prefix replaces the direct start-value write with a full setter
  notification, so the UI never receives the empty reset value.

Native ScheduleAutoUpdate can call UpdateValue synchronously for a zero start
delay. Reentrancy guards allow the full setter while still suppressing nested
drain ticks. Rates, intervals, start values and input/ability gates are not
changed. UV still uses the user's normal control and native gameplay gates.
When the captured player loses eligibility or a scene changes, references are
cleared and native scheduling is resumed once if the old live battery had its
update loop suppressed. A release guard permits that native scheduling without
recapturing the departing player. No forced UV input or network event is sent.

The UV hooks have their own Harmony owner and setup/runtime errors. A UV setup
failure unpatches UV alone; freeze and flight remain available. Reports include
UnlimitedUvReady, UnlimitedUvSetupError and the adapter's active/fault state,
last player/pointer/difficulty/charge/capacity, refill count, blocked scheduled
ticks, rewritten setter values and blocked resets. F9 and EXPORT_REPORT.cmd
retain the existing extracted-package Reports destination.

EXISTING CONTROLS
Left click alone remains DEVOUR's normal run action. A right-only click toggles
no-clip on release. Both held together toggle freeze once, consume the right
click, and require both released before rearming. Either press order works.
Mapped joystick movement, native turning/headset look, held jump/crouch,
head/controller/character direction, keyboard controls, local identity,
collision recovery and lifecycle restoration remain byte-identical to v0.3.1.
The overlay still has exactly three labels: version, Freeze, No-clip.
